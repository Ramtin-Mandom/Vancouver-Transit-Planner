# v1.0.0 release notes — draft

Vancouver Transit Planner 1.0.0 presents a portfolio-ready, reliability-aware
journey planner for Metro Vancouver scheduled transit.

## Highlights

- Compare scheduled routes using travel time and historical reliability.
- Choose production snapshot A* or Dijkstra through a validated public API.
- Request one route or up to three selectable alternatives.
- View explicit planner-not-ready, timeout, expired-feed, no-route, input, and
  network states.
- Serve production requests from a versioned memory-mapped snapshot without a
  runtime PostgreSQL dependency.
- Rebuild snapshots from PostgreSQL after GTFS ingestion and reliability
  aggregation.

## Engineering notes

The snapshot search indexes transfers, validates optional geographic A* speed
bounds, supports GTFS times beyond 24 hours, and reports candidate/resource
limits truthfully. Reliability profile selection is shared across snapshot and
database modes and reports the level actually used.

The repository retains baseline/database routing, MC-RAPTOR, older A*, and all
cache variants for experiments. They are not exposed as unsupported production
choices.

## Deployment

`main` is the only deployment branch. Render URLs, CORS origins, database build
credentials, and the frontend API URL must be configured by the release
operator. No deployment or release was performed while preparing this draft.

## Limitations

The frontend service-date selector is not implemented. Reliability depends on
available observation samples. Alternative search is candidate-bounded. A*
geographic acceleration safely disables itself when the snapshot cannot prove a
valid speed bound. TransLink, OpenStreetMap, and Google Fonts remain third-party
data/service dependencies subject to their own terms.
